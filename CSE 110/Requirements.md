### How to make Requirements

First, what the system must do (functional)
- Scenarios can be used to think of requirements
- User Stories:
	- As a [stakeholder], I want [something] so that [need].
	- As a student, I want to filter recipes by cost so I can keep dinner under $5 per person
- User story criteria INVEST:
	- Independent - so we can implement them in any order and at the same time for efficiency, although this is not guaranteed most of the time
	- Negotiable - details can be negotiated during development, meaning to only require about big picture stuff, and none of the specifics
	- Valuable - needs to have value to someone, hopefully the user
	- Estimable - helps to keep the size small, not too vague or too hard
	- Small - fit on 3x5 card, at most two person-weeks of work
	- Testable - Ensures clarity, so we know when the task is done, so it should be a little more precise in that account
